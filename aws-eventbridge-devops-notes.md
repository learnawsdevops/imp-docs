# AWS EventBridge – Practical DevOps Notes

## 1. What is Amazon EventBridge?

Amazon EventBridge is a serverless event-routing service in AWS.

It helps different AWS services and applications communicate with each other using events.

Instead of continuously checking whether something has happened, we can configure EventBridge to listen for events and trigger actions automatically.

**Simple example:**

When an EC2 instance is stopped:

1. EC2 generates an event.
2. EventBridge receives the event.
3. An EventBridge rule checks the event.
4. If the event matches the configured conditions, EventBridge triggers an action.
5. SNS sends an email notification.

---

## 2. What is an Event Bus?

An Event Bus is the central entry point that receives events and routes them to the appropriate rules.

EventBridge provides different types of event buses.

### 2.1 Default Event Bus

- AWS creates it automatically in every AWS account.
- Primarily receives events generated by AWS services.
- No need to create or configure an event bus manually.
- Useful for monitoring AWS infrastructure and service activities.

**Examples:**

- EC2 instance state changes.
- ECS task state changes.
- CodePipeline execution failures.
- AWS Health events.
- S3 events when configured to publish through EventBridge.

### 2.2 Custom Event Bus

- Created manually by users.
- Primarily used for custom application events.
- Applications can publish their own events using the AWS SDK or PutEvents API.
- Helps different applications communicate without directly depending on each other.

**Example:**

Imagine an application with three services:

1. User Service
2. Payment Service
3. Order Service

When payment is completed, the Payment Service publishes a `PaymentCompleted` event.

EventBridge receives it through a custom event bus.

Multiple rules can trigger different actions:

- Send an email notification.
- Update the order using Lambda.
- Generate an invoice.
- Trigger another application workflow.

### Default vs Custom Event Bus

| Feature          | Default Bus               | Custom Bus                              |
| ---------------- | ------------------------- | --------------------------------------- |
| Creation         | AWS automatically         | User creates                            |
| Main purpose     | AWS service events        | Application events                      |
| Event publishers | AWS services              | Applications and supported AWS services |
| Common use       | Infrastructure monitoring | Application integration                 |
| Configuration    | Already available         | Requires creation and configuration     |

**Remember:**

- Default Event Bus = React to AWS events.
- Custom Event Bus = Connect your applications through events.

## 3. How EventBridge Works

The typical EventBridge workflow:

```
Event Source
     |
     v
Event Bus
     |
     v
EventBridge Rule
     |
     v
Event Pattern Matching
     |
     v
Target
     |
     +---- Lambda
     |
     +---- SNS
     |
     +---- SQS
     |
     +---- Step Functions
```

### Components Explained

**Event Source**

The service or application that generates an event.

Examples: EC2, S3, CodePipeline or a custom application.

**Event Bus**

Receives incoming events and makes them available for matching rules.

**EventBridge Rule**

Defines which events should trigger an action.

**Event Pattern**

Specifies the conditions that an incoming event must satisfy.

**Target**

The destination that receives the matched event.

Examples: Lambda, SNS, SQS and Step Functions.

---

## 4. What is an EventBridge Rule?

An EventBridge rule determines which events should be processed.

For example, imagine we want to receive an email only when an EC2 instance is stopped.

We create a rule with the following event pattern:

```
{
  "source": ["aws.ec2"],
  "detail-type": [
    "EC2 Instance State-change Notification"
  ],
  "detail": {
    "state": ["stopped"]
  }
}
```

### Understanding the Event Pattern

- `source`: Identifies which AWS service generated the event.
- `detail-type`: Identifies the type of event.
- `detail.state`: Checks the EC2 instance state.

The rule matches only when an EC2 instance enters the stopped state.

Other states, such as running or terminated, will not match this particular rule.

---

## 5. Understanding an EC2 State Change Event

When an EC2 instance changes its state, AWS generates an event.

Example:

```
{
  "version": "0",
  "id": "example-event-id",
  "source": "aws.ec2",
  "detail-type": "EC2 Instance State-change Notification",
  "time": "2026-11-22T08:14:02Z",
  "region": "ap-south-1",
  "account": "440922630000",
  "detail": {
    "instance-id": "i-093467895968abc3e",
    "state": "stopped"
  }
}
```

### Important Fields

| Field              | Meaning                      |
| ------------------ | ---------------------------- |
| version            | Event format version         |
| id                 | Unique event identifier      |
| source             | Service generating the event |
| detail-type        | Type of event                |
| time               | Event generation timestamp   |
| region             | AWS region                   |
| account            | AWS account ID               |
| detail.instance-id | EC2 instance ID              |
| detail.state       | Current EC2 state            |

**Important:** The `instance-id` and `state` fields are inside the `detail` object. Other fields like `region`, `account`, and `time` are at the root level.

## 6. What is an EventBridge Target?

A target is the destination to which EventBridge sends a matched event.

Common targets:

| Target         | Purpose                      |
| -------------- | ---------------------------- |
| Lambda         | Execute custom code          |
| SNS            | Send notifications           |
| SQS            | Queue messages               |
| Step Functions | Execute multi-step workflows |
| ECS            | Run containerized tasks      |

### Practical Example

```
EC2 Instance Stopped
        |
        v
EventBridge Rule
        |
        v
SNS Topic
        |
        v
Email Subscription
        |
        v
DevOps Team Receives Email
```

---

## 7. What is SNS?

Amazon Simple Notification Service (SNS) is a fully managed messaging service.

It allows publishers to send messages to subscribers.

In our example:

- EventBridge is the publisher.
- SNS Topic receives the message.
- Email subscription receives the notification.

### SNS Topic

A topic is a logical communication channel.

Multiple subscribers can subscribe to the same topic.

Example:

```
EventBridge
     |
     v
SNS Topic: EC2-Monitoring
     |
     +---- DevOps Email
     |
     +---- Admin Email
     |
     +---- HTTPS Endpoint
```

When SNS receives a message, it distributes it to the subscribed endpoints.

## 8. What is Input Transformer?

By default, EventBridge can send the complete event JSON to its target.

However, sometimes we don't need the complete event.

For example, we only need:

- Instance ID
- Instance State
- AWS Region
- Account ID
- Event Time

Input Transformer helps extract selected fields from an event and construct a customized message.

It has two components:

1. Input Paths
2. Input Template

### 8.1 Input Paths

Input Paths define which fields should be extracted from the original event.

Example:

```
{
  "instanceId": "$.detail.instance-id",
  "state": "$.detail.state",
  "region": "$.region",
  "account": "$.account",
  "eventTime": "$.time"
}
```

Understanding:

| Variable   | JSON Path            |
| ---------- | -------------------- |
| instanceId | $.detail.instance-id |
| state      | $.detail.state       |
| region     | $.region             |
| account    | $.account            |
| eventTime  | $.time               |

The extracted values are stored in variables that can be referenced in the Input Template.

### 8.2 Input Template

The Input Template defines the final message sent to the target.

Example:

```
"Hello DevOps Team,\n\nAn EC2 instance state change was detected.\n\nInstance ID: <instanceId>\nCurrent State: <state>\nAWS Region: <region>\nAccount ID: <account>\nEvent Time: <eventTime>\n\nPlease investigate if this change was unexpected.\n\nRegards,\nAWS Monitoring"
```

Here:

- `<instanceId>` is replaced with the actual EC2 instance ID.
- `<state>` is replaced with the actual instance state.
- `<region>` is replaced with the AWS region.
- `<account>` is replaced with the account ID.
- `<eventTime>` is replaced with the event timestamp.
- `\n` represents a newline in the JSON string.

**Important:** The complete template is a JSON string. Use escaped newline characters (`\n`) rather than placing literal line breaks inside the quoted JSON string.

## 9. Troubleshooting Input Transformer

### Issue 1: Values are showing as null

Possible reasons:

- Incorrect JSON paths.
- Incorrect event structure.
- Variable names in Input Template do not match Input Paths.
- The selected sample event does not contain the expected fields.

**Solution:**

Verify the original event JSON and make sure the paths match its structure.

For example:

Correct:

```
$.detail.instance-id
$.detail.state
```

Incorrect:

```
$.instance-id
$.state
```

### Issue 2: Email is received as a single paragraph

SNS email notifications are plain-text messages, but formatting can depend on how the message is generated and rendered.

Check the following:

1. Use `\n` in the Input Template.
2. Use EventBridge's Generate output feature to verify the generated message.
3. Check whether the generated output contains actual line breaks or literal escape sequences.
4. Test the notification in another email client if necessary.

If reliable HTML formatting, custom email subjects or branded email templates are required, consider:

```
EventBridge
    |
    v
Lambda
    |
    v
Amazon SES
    |
    v
Formatted HTML Email
```

## 10. Practical Project: EC2 State Change Email Notification

### Objective

Automatically send an email whenever an EC2 instance enters the stopped state.

### Architecture

```
EC2 Instance
     |
     | State Change Event
     v
Default Event Bus
     |
     v
EventBridge Rule
     |
     | Match: state = stopped
     v
SNS Topic
     |
     v
Email Subscription
     |
     v
DevOps Team
```

### Implementation Steps

**Step 1: Launch EC2**

Launch an EC2 instance in the ap-south-1 region.

**Step 2: Create SNS Topic**

1. Open Amazon SNS.
2. Navigate to Topics.
3. Create a Standard topic.
4. Give it a name such as `EC2-Monitoring`.

**Step 3: Create Email Subscription**

1. Open the SNS topic.
2. Create a subscription.
3. Select Email as the protocol.
4. Enter your email address.
5. Confirm the subscription using the email received.

**Step 4: Create EventBridge Rule**

1. Open Amazon EventBridge.
2. Navigate to Rules.
3. Select the Default Event Bus.
4. Create a rule named `EC2-Stopped-Notification`.
5. Select the AWS service event source.
6. Select EC2 and the EC2 Instance State-change Notification event type.
7. Configure the event pattern to match `stopped`.

**Step 5: Configure Target**

1. Select SNS Topic as the target.
2. Select the `EC2-Monitoring` topic.
3. Configure target input.
4. Select Input Transformer.
5. Configure Input Paths.
6. Configure Input Template.
7. Save the rule.

**Step 6: Test**

1. Stop your EC2 instance.
2. Wait for the state-change event.
3. Check your subscribed email.
4. Verify the instance ID, state, region and event time.

### Expected Email

```
Hello DevOps Team,

An EC2 instance state change was detected.

Instance ID: i-093467895968abc3e
Current State: stopped
AWS Region: ap-south-1
Account ID: 440922630000
Event Time: 2026-11-22T08:14:02Z

Please investigate if this change was unexpected.

Regards,
AWS Monitoring
```

## 12. Important Concepts to Remember

| Concept           | Simple Explanation                  |
| ----------------- | ----------------------------------- |
| Event             | Something that happened             |
| Event Bus         | Receives events                     |
| Event Source      | Generates events                    |
| Event Pattern     | Defines which events should match   |
| Rule              | Connects matching events to targets |
| Target            | Receives the matched event          |
| Input Transformer | Extracts and formats event data     |
| SNS Topic         | Distributes messages to subscribers |
| Subscription      | Defines where SNS sends messages    |

### Final Takeaway

Think of EventBridge as a central event receptionist.

1. Different AWS services generate events.
2. EventBridge receives those events.
3. Rules check whether an event matches specific conditions.
4. Matching events are routed to configured targets.
5. Targets perform the required actions.

**EventBridge = Event Routing and Automation.**

**SNS = Message Distribution and Notifications.**

**Lambda = Custom Code Execution.**

**Step Functions = Workflow Orchestration.**
