ALB, Target Group and ASG: who does what?

Three services that always show up together. Read top to bottom once, then use the quiz and cheat sheet to lock it in.

ALB decides where each request goes. Target Group is the list of healthy places it can go. ASG keeps that list full by adding and removing servers.

Think of a restaurant

ALB = the host

Greets every guest, reads what they want (path, host name) and sends them to the right section.

Target Group = the table list

Only tables that are clean and ready are on it. A broken table gets crossed off (failed health check).

ASG = the manager

Busy night? Opens more tables. Quiet? Closes some. Table breaks? Replaces it.

    One card per concept

    ALB

    • Layer 7 (understands HTTP)
    • Listener = port + protocol
    • Rules route by path, host, header
    • Needs 2+ AZs, has a security group
    Remember: ALB never points at servers directly. It points at a Target Group.

    Target Group

    • Target type: instance, IP, Lambda
    • Runs health checks
    • Only healthy targets get traffic
    • Has deregistration delay and stickiness
    Remember: The TG is the meeting point. ALB reads it, ASG writes to it.

    ASG

    • Launch template = the blueprint
    • Min / Desired / Max
    • Scaling policies add or remove
    • Replaces unhealthy instances
    Remember: ASG is attached to the TG. That link is the magic.

    Common mix-ups

    ALB or NLB? ALB for HTTP/HTTPS and smart routing (Layer 7). NLB for TCP/UDP, extreme speed, static IPs (Layer 4).
    Unhealthy in TG, but ASG did nothing? The ASG health check type is still EC2. Switch it to ELB.
    Is cross-zone load balancing optional? On an ALB it is always on. On an NLB you choose.
    Who stops a bad server getting traffic? The Target Group (health check). Who replaces it? The ASG.
    Scale on what? For web apps, ALBRequestCountPerTarget in a target tracking policy is the cleanest signal.

    Cheat sheet

    Flow: User → ALB (listener, rule) → Target Group (healthy only) → EC2 in ASG
    ALB: routes by path, host, header. Layer 7. 2+ AZs.
    TG: health check path returns 200 · dereg delay 300s · interval 30s · unhealthy 2 · healthy 5
    ASG: min / desired / max · launch template · health check type ELB · grace period over boot time
    Glue: ASG attached to TG → auto register and deregister
    Must match: TG port = app port · instance SG allows ALB SG · health path = 200
